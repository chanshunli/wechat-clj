# 随机性不是噪声，是搜索工具——从 GPT 的采样到物理世界的演化

> 姊妹篇：`docs/gpt_as_search_evolution.md`（《把 GPT 当作"更高级的万能谷歌搜索"》）
>
> 上一篇说的是**搜索的载体**怎么从字符串演化到高维语义流形；
> 这一篇说的是**搜索的动力**——在一个没有索引、没有梯度的空间里，你靠什么迈出下一步。
> 答案是：**随机性**。

---

## 一、这句话到底在说什么

"随机性不是噪声，是搜索工具"，本质是在做一次**视角切换**：

| 视角 | 随机性是什么 | 你的目标 |
|------|--------------|----------|
| 信号处理视角（经典） | 混进信号里的扰动 | **消除它**——滤波、平均、提高信噪比 |
| 搜索视角 | 生成候选解的算子 | **调度它**——什么时候放大，什么时候收紧 |

同一个 `ε`，在通信工程里是敌人，在优化里是唯一能让你离开当前位置的东西。

判据其实很简单：

> **随机性 + 选择 + 记忆 = 搜索。**
> 缺任何一项，它就退化成噪声。

- 只有随机性，没有**选择**（评价函数） → 布朗运动，原地打转。
- 有随机性和选择，没有**记忆**（把好结果留下来的机制） → 每轮从零开始，白搜。
- 三者齐全 → 你就有了一台不需要梯度、不需要索引的搜索引擎。

这三项在不同系统里的化身，就是本文剩下要讲的东西。

## 二、和《搜索进化史》的联系：随机性是"第三个动作"的引擎

上一篇把 GPT 的生成拆成三个动作：**搜索 → 拼接 → 过滤**。
但那篇文章留了一个洞没有补：**在一个连续的高维空间里，"搜索"这个动作具体怎么执行？**

关键词搜索有倒排索引，向量搜索有 ANN，它们都有**现成的地址**可以跳过去。
而 GPT 的语义流形里没有地址——它只有一个概率分布 `P(next_token | context)`。
从分布到具体的一条路径，中间只有一种操作：**采样**。

所以：

| 搜索时代 | "取下一个候选"靠什么 | 随机性的角色 |
|----------|---------------------|--------------|
| 1. 关键词搜索 | 倒排索引查表 | 无（确定性） |
| 2. 向量搜索 | ANN 近邻 | 建索引时有（LSH/随机投影），查询时基本无 |
| 3. 高维 RAG | 近邻 + 重排 | 弱 |
| 4. 生成式搜索 | **从 `softmax` 分布里采样** | **核心机制**——没有它就只剩一条贪心路径 |

于是，上一篇里那些看起来很"玄"的推理超参数，全都变成了**搜索控制旋钮**：

| 超参数 | 搜索语义 |
|--------|----------|
| `temperature` | **搜索半径**。趋近 0 = 贪心爬山；调高 = 允许翻过山脊 |
| `top-p` / `top-k` | **搜索空间剪枝**。先把明显是垃圾的方向砍掉，再在剩下的里面随机走 |
| `n` / best-of-n | **并行搜索的分支数**。一次撒 n 个探针，再用打分器选一个 |
| beam search | **确定性宽度优先**——注意它恰恰是"用宽度换掉随机性"，所以在开放生成上反而更容易退化 |
| `pass@k` | 一个**承认搜索是随机的**评测指标：给 k 次机会，看能不能搜到 |

`pass@k` 这个指标本身就是最好的证据。如果随机性只是噪声，那 `pass@1` 和 `pass@10` 应该差不多；
现实是很多模型 `pass@1` 只有 20%，`pass@10` 能到 60%——**这 40 个百分点就是随机性搜出来的**，
它不在权重里"多"出来，它一直在分布里，只是需要多采几次才碰得到。

### 训练侧同理

- **SGD 的 minibatch 噪声**：不是"为了省显存不得不接受的误差"，它是逃离尖锐极小值、提升泛化的正则化机制。
- **dropout**：在结构空间里随机搜索一个子网络集成。
- **参数初始化**：全零初始化会让所有神经元对称、永远学不出东西——**随机性在这里是打破对称性的唯一手段**。
- **RL rollout（本仓库的 GRPO）**：这是最赤裸的一条。GRPO 对同一个 prompt 采样一组 G 条轨迹，
  用组内相对优势构造梯度。**如果采样没有随机性，G 条轨迹完全一样，组内方差为 0，梯度就是 0——训练直接停摆。**
  换句话说：*RL 的学习信号完全是随机性生产出来的。*
  （见 `docs/rl_algorithms.md`、`docs/swebench_rl.md`）

  推论：**entropy collapse 是 RL 训练里最该盯的指标之一**。熵塌了不是"模型收敛了"，是"搜索工具坏了"——
  模型不再产生多样候选，reward 曲线会先漂亮地涨一段然后卡死。KL 惩罚、熵正则、温度调度，
  本质上都是在**保护随机性这件工具不被优化过程磨钝**。

- **扩散模型**：把这件事推到了极致——它干脆把**噪声本身当作搜索的介质和起点**，
  从纯高斯噪声出发，一步步把随机性"雕刻"成样本。噪声在这里不是要滤掉的东西，是原材料。

## 三、为什么非随机不可

不是因为随机好，是因为**确定性方法在这类空间里用不了**：

1. **没有梯度**：代码能不能通过测试、分子能不能结合，这些评价函数不可微，你没法沿梯度走。
2. **组合爆炸**：一段 200 token 的程序，候选空间是 `|V|^200`。穷举不可能，需要**有偏采样**。
3. **局部最优**：确定性爬山必然停在第一个山顶。跳出去只有两条路——要么有全局信息（没有），要么随机扰动。
4. **No Free Lunch**：在没有先验的情况下，任何确定性策略都会在某类问题上系统性地失败；随机化策略至少有**保底的期望性能**，且对抗不了它。
5. **可并行**：随机搜索天然可以撒 n 个探针并行跑，确定性串行搜索不行。这在工程上极重要——best-of-n 是最便宜的"加算力换性能"。

所以随机搜索的成立条件是：**你不需要知道路怎么走，你只需要能判断走到的地方好不好。**
把"求解"降级成"评价"——这是随机性能作为工具的全部前提。

## 四、物理世界对应的搜索是什么

问题的第三部分：如果 GPT 在语义空间里搜索，那**物理世界在搜索什么、用什么搜**？

答案不止一个，而是一个**同构家族**。它们都满足"随机性 + 选择 + 记忆"三件套：

### 1. 生物演化——最古老、最著名的一台搜索引擎

| 搜索三动作 | 生物学对应 |
|------------|-----------|
| 生成候选（随机） | **突变**：复制错误、辐射、转座子。这是生物界的 `temperature` |
| 拼接 | **有性生殖 / 重组**：把两条已验证的解交叉出新解（等价于 GA 的 crossover，也等价于 GPT 的 attention 融合多段上下文） |
| 过滤 | **自然选择**：环境就是评价函数，它不需要可微，只需要能判死活 |
| 记忆 | **DNA**：把搜到的好解存下来，下一轮从这里而不是从零开始 |

对照关系惊人地整齐：
- **突变率 = temperature**。太低 → 物种僵化，环境一变就灭绝（等价于 greedy decoding 的重复退化）；
  太高 → 误差灾难（error catastrophe），基因组信息保不住（等价于 temperature 调到 5 输出乱码）。
  生命把突变率精细调控在一个窄带里——这就是**温度调度**。
- **种群规模 = best-of-n 的 n**。种群越大，并行探针越多。
- **物种形成 = 多样性保持**，防止整个搜索坍缩到一个模态（正是 entropy collapse 的反面）。
- **进化不需要"设计者"，正如 GPT 不需要"检索出确切的那篇文档"**——两者都是在无索引空间里靠采样 + 选择走出来的。

> 生物演化是地球上跑了 38 亿年、并行度约 10³⁰ 的随机搜索。
> 它的产物（眼睛、ATP 合酶、大脑）之所以看着像被设计过，正是因为**随机性配上选择和记忆，就是设计**。

### 2. 热力学与退火——温度就是字面意义上的温度

**模拟退火**这个算法不是比喻，它是从冶金学**直接抄来**的：

- 金属高温时原子随机剧烈运动 → 能跳出局部的应力构型（大 temperature，大范围搜索）。
- 缓慢降温 → 原子逐渐锁定在低能构型，长成大而完整的晶体（退火调度）。
- 骤冷（quench）→ 卡在无序的玻璃态，就是**陷入局部最优**。

所以物理世界的"搜索"，在最基础的层面上就是**热运动在能量地形（energy landscape）上找低点**。
`exp(-E/kT)` 的玻尔兹曼分布和 `softmax(logits/T)` 是**同一个公式**——LLM 采样里的 `T` 叫 temperature，
不是巧合，是同一件事。

同一台机器还解释了：
- **蛋白质折叠**：Levinthal 悖论说穷举所有构象要比宇宙年龄还久，但蛋白在毫秒内折好了。
  因为它不是穷举，是**热噪声驱动的漏斗形能量地形上的随机下降**。噪声是折叠的动力，不是障碍。
- **结晶、相变、自组装**：都是"随机涨落 + 能量选择"。

### 3. 分子尺度——布朗运动是细胞的检索算法

一个酶要在细胞里找到它的底物，一个转录因子要在 3×10⁹ 碱基里找到那一小段序列。
它们没有地址，没有指针。它们用的是**扩散**：随机碰撞，碰对了就结合（结合能就是评价函数）。

- 这是**纯粹的随机搜索**，而且被证明在这个尺度上是最优的——分子太小，定向运动的成本高于随机撞击。
- 更漂亮的是**分子马达**（如驱动蛋白）：它们是"棘轮"——**利用热噪声提供运动，用 ATP 只负责单向棘齿**。
  也就是说，生命不是在对抗热噪声，而是**把热噪声当发动机**，自己只提供选择（整流）。
  这是"随机性不是噪声，是工具"最字面的物理实现。

### 4. 免疫系统——一台在体内运行的在线 RL

这是所有类比里和 LLM 训练最像的：

| 免疫机制 | 机器学习对应 |
|----------|--------------|
| V(D)J 重组，随机拼出 ~10¹¹ 种抗体 | **大规模随机初始化 / 预训练覆盖广域** |
| 阴性选择，删掉攻击自身的克隆 | **安全对齐 / 拒答训练** |
| 抗原结合作为奖励信号 | **reward model** |
| 体细胞超突变 + 亲和力成熟 | **RL 微调**：在当前最好解附近定向加噪、再选择 |
| 记忆 B 细胞 | **权重更新 / 经验回放** |

注意亲和力成熟的细节：它**只在已经结合上的克隆附近提高突变率**。
这正是"先粗搜、再在好区域精搜"的**自适应温度调度**，而且是免疫系统自己长出来的。

### 5. 人类尺度——科学、市场、创造

- **科学方法**：假设（随机生成候选）→ 实验（评价函数）→ 论文/教科书（记忆）。
  科学之所以有效，不是因为科学家能直接推出真理，是因为它建立了一套**便宜且诚实的评价机制**。
- **市场经济 / 创业**：大量创业公司是并行随机探针，市场是选择压力，制度和资本是记忆。
  "为什么必须允许失败" —— 因为**失败样本是搜索的必要开销**，禁止失败等于把 temperature 设成 0。
- **A/B 测试**：把随机化直接制度化成产品决策工具。
- **创造力**：直觉上"灵感"像随机联想 + 品味筛选。这也解释了为什么 `temperature=0` 的模型写不出有意思的东西——
  **你不能既要确定性又要新颖性，这两个是同一个旋钮的两端。**

### 6. 一张总表

| | 候选生成（随机源） | 拼接 | 选择（评价函数） | 记忆 | 温度旋钮 |
|---|---|---|---|---|---|
| 关键词搜索 | 无 | 人工 | 点击率 | 索引 | 无 |
| GPT 推理 | softmax 采样 | attention | logprob / reward model | 权重 + 上下文 | `temperature` |
| RL 训练 (GRPO) | rollout 采样 | — | 单测/Docker 通过率 | 参数更新 | 采样温度 + KL/熵正则 |
| 生物演化 | 突变 | 重组 | 生存繁殖 | DNA | 突变率 |
| 热力学/退火 | 热涨落 | — | 能量 | 构型 | 真·温度 |
| 分子搜索 | 布朗运动 | 结合 | 结合自由能 | 复合物 | 环境温度 |
| 免疫系统 | V(D)J + 超突变 | 重组 | 抗原亲和力 | 记忆细胞 | 超突变率 |
| 科学/市场 | 假设/创业 | 综合 | 实验/利润 | 文献/制度 | 冒险偏好 |

**共同结构**：在一个大到无法枚举、且没有可用梯度的空间里，
用随机性造候选，用便宜的评价函数杀候选，用某种存储把幸存者传下去。
这不是八个不同的现象，是**同一个算法的八次独立实现**。

## 五、什么时候随机性真的只是噪声

这篇文章不是说"随机总是好的"。反过来的判据同样重要——**下面任一条不满足，随机性就退化回噪声**：

1. **评价函数太贵或太慢**。搜索的成本 ≈ 采样次数 × 评价成本。
   SWE-bench 的 RL 要跑 Docker 起容器跑测试，评价一次几十秒——这就是为什么要做分层奖励、
   先用便宜的格式奖励筛掉大部分垃圾（见 `docs/swebench_rl.md`）。**便宜的评价函数是随机搜索的生命线。**
2. **评价函数不诚实**。reward hacking 就是这个：选择压力指向了错的方向，随机性会**加速**你走向错误。
   随机性是放大器，它不判断方向。
3. **没有留存机制**。每次采样都从头开始、结果不回流到权重/数据里，那就是纯烧钱。
4. **尺度不对**。温度太高 → 误差灾难 / 输出乱码；太低 → 重复退化 / 物种僵化。
   随机性的**幅度必须和地形的粗糙度匹配**，而且通常需要随时间衰减。
5. **场景本身要求可复现**。计费、编译、加密签名——这些地方的随机性是纯粹的 bug。
   `temperature=0` 存在是有道理的，只是别把它当默认哲学。

## 六、落到本仓库的工程动作

| 动作 | 在做什么 |
|------|----------|
| 推理时给代码任务留 `temperature≈0.6–0.8` 而不是 0 | 保住搜索半径，配合单测做 best-of-n |
| 评测用 `pass@k` 而不只是 `pass@1` | 承认能力是"分布里的可达性"，不是"一次就中" |
| RL 阶段监控 rollout 的熵和组内 reward 方差 | 方差趋零 = 搜索死了，比 loss 更早预警（`docs/rl_algorithms.md`） |
| 分层 reward：格式 → apply → 测试通过 | 把昂贵的评价函数拆成便宜的前置滤网（`docs/swebench_rl.md`） |
| 拒绝采样微调 / Expert Iteration | 最直白的"搜索 → 把搜到的好解写回权重"闭环 |
| 数据侧保留难负例、控制配比 | 塑造选择压力的形状（`docs/mixed_sft_vs_moe.md`） |

## 七、一句话总结

> 上一篇说：**GPT 是把搜索从关键词推进到高维语义流形的搜索引擎。**
>
> 这一篇说：**在那个流形上，唯一能迈步的方式是采样——所以随机性不是搜索的副作用，它就是搜索本身。**
>
> 而物理世界早就用同一套算法跑了 38 亿年：
> **突变是它的 temperature，自然选择是它的 reward model，DNA 是它的权重。**
> 演化、退火、扩散、免疫、市场、GPT——是同一个搜索算法在不同衬底上的六次实现。
>
> 所以工程上真正的问题从来不是"怎么消除随机性"，而是：
> **你的评价函数够不够便宜、够不够诚实，以及你的温度调度对不对。**
